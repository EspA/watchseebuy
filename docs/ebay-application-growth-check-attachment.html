1. What WatchSeeBuy is

WatchSeeBuy helps collectible buyers — cards, LEGO, vintage toys, and similar lines — decide whether an eBay listing is worth buying at the price to their door (item + shipping + a simple import/tax estimate). Collectors search listings, save intent watches, and receive email when a match appears. Purchase always happens on eBay. We are not a seller tool, not a scraper, and not an auction sniper.

The product is live. The number of users is growing quickly, which increases public searches and saved watches. Search and watch coverage share one Browse daily quota. The default 5,000 calls/day cannot sustain that growth. We request 250,000 Browse calls/day as soon as possible so search and alerts remain available.

2. Main features

Public search

Anyone can search without an account. The collector types the piece (for example a PSA 10 card, a factory-sealed set, or a carded figure) and optional filters: condition language, listing type, item location, ship-to ZIP or country, and a maximum price to their door. Results come only from the official Buy Browse API. The browser never calls eBay.

Price to your door, price score, seller score

Every result shows the all-in price to the collector’s address, a price score versus similar listings in that result set, and a seller score from feedback. We do not hide fees behind a sign-in wall.

Intent watches

Saving a watch and receiving alerts requires a WatchSeeBuy account (Google, Apple, Facebook, or email magic link). A watch stores the collector’s meaning — piece, condition, max price to their door, location — not a raw clone of eBay saved-search parameters. Free accounts may save a limited number of watches.

Quiet alerts

The collector chooses cadence: when a new matching listing appears, a daily note, or a weekly recap (8pm in their timezone). Emails include the same listing card as search. Volume is not the product; accuracy is. We do not compete on sub-minute polling.

Buy on eBay (EPN)

Buy always lands on the eBay item page. Clicks go through a first-party WatchSeeBuy URL, then to eBay with Partner Network parameters for publisher your-epn-publisher-id. We use a text “Buy on eBay” link, not the eBay logo. If an ad blocker strips affiliate parameters, we still open the plain item URL so the collector can complete the purchase. In-app checkout (Buy APIs) is not used.

3. Official eBay APIs only

One shared TypeScript client, one application (client-credentials) OAuth token. Users never authenticate to eBay through us. We do not collect eBay passwords or user tokens.

API Call Use
Buy Browse GET /buy/browse/v1/item_summary/search Public search and hourly coverage polls. Limit 24. Field group EXTENDED.
Buy Browse GET /buy/browse/v1/item/{itemId} Hydrate filtered listings only (PRODUCT). Unique IDs. Concurrency cap 5.
Identity POST /identity/v1/oauth2/token Application token, cached in process until near expiry.
Commerce Notification GET /commerce/notification/v1/public_key/{kid} Verify X-EBAY-SIGNATURE on marketplace account-deletion POSTs. Key cached 1 hour.

We do not call Trading, Finding, Feed, bulk getItems (Limited Release), or Order / in-app checkout APIs.

4. Efficient use of quota

The hard problem is eBay quota, not HTTP. We designed the data model so we never poll once per user.

  • Coverage-query coalescing. Many watches compile to the same coarser eBay search (keywords, category, condition class, site). The worker polls each due query about once per hour, then matches listings in process.
  • getItem after local filters. Landed-cost, condition, listing type, location, and confidence filters run on search summaries first. Only remaining listings are hydrated.
  • Seen listings. Postgres unique (watch, item) so we do not alert twice or re-fetch for a duplicate match.
  • Single client. Token cache, concurrency cap of 5, no tight retry loop on failure. Search returns an empty result; getItem returns null.

As users grow, both public searches and distinct coverage queries increase, but they share one Browse daily bucket. Formula we use for capacity planning (not a claim of current measured volume):

calls/day ≈ (shared coverage queries × 24 hourly polls + public searches) × (1 + getItems after filters)

Requested Browse capacity: 250,000 calls/day. Peak-hour planning: about 1,000 searches and 5,000 getItem calls if a search burst coincides with a worker tick. Identity and Notification traffic stays small.

5. Security (not on the short form)

TopicHow WatchSeeBuy handles it
Password collection No eBay passwords. Collectors sign in to WatchSeeBuy only (SSO or magic link). Optional WatchSeeBuy password is hashed. eBay credentials live in GCP Secret Manager, never in the browser or a public repo.
Auth / OAuth Application client-credentials token only. There is no end-user Auth’n’Auth or user-token flow for reviewers to click through. Test public search at https://watchseebuy.com/search.
Denial of service Public search is the only unauthenticated eBay-backed surface. Watch create and alerts require a session. We log every eBay call and stop hydrating when search fails. HTTPS on Cloud Run. We will not add per-user eBay polling.
XSS Next.js / React escapes rendered text. Collector queries are parsed server-side into structured criteria, then sent as Browse query parameters. Users cannot inject HTML or arbitrary eBay payloads. Listing titles and images are data, not markup.
SQL injection Postgres via Drizzle parameterized queries. Search strings are not concatenated into SQL. Coverage keys and item IDs are bound parameters.
CSRF Watch create is a same-origin form POST behind a Better Auth session cookie. Collectors cannot make our server call eBay as another user. There is no end-user eBay token to steal.
System / application errors Every eBay call is logged with API name, source (web search, worker poll, account deletion), success, HTTP status, and duration — including 429s. We do not hammer retries. Process errors go to Cloud Logging. Operators review call health in an internal admin console.
Logging / messages We log status and timing for operator review, not full listing dumps or secrets.
Simultaneous threads getItem concurrency is 5. The worker polls coverage queries sequentially in a tick. A small number of Cloud Run web instances may run in parallel under load.

6. Marketplace user account deletion

Production keys register https://watchseebuy.com/api/ebay/account-deletion.

  • GET answers eBay’s SHA-256 challenge (challengeCode + verificationToken + exact endpoint URL).
  • POST verifies X-EBAY-SIGNATURE via Notification API getPublicKey, then strips that seller’s username from cached listing snapshots.

7. Privacy and affiliate disclosure

Privacy policy and terms are public. Search may include an optional ship-to ZIP. Account data is email and profile fields from the sign-in provider. We do not post to social accounts. Affiliate relationship is disclosed in the product UI. We do not cloak EPN links.

8. What this application is not

  • Not a scraper or unofficial HTML harvest.
  • Not auction sniping or a 15-second flipper alert.
  • Not a multi-marketplace reseller dashboard.
  • Not a clone of eBay browse; we do not use “eBay” or “Bay” in the brand or domain.
  • Not in-app checkout. Buy is a handoff to the eBay item page.
